Event Loop:
JavaScript is single-threaded, so it executes JavaScript code using a call stack. For asynchronous operations, the runtime uses Web APIs and queues. The event loop continuously checks whether the call stack is empty and then moves eligible callbacks from the queues to the call stack.
Promise vs setTimeout:
 console.log("A");

setTimeout(() => {
    console.log("B");
}, 0);

Promise.resolve().then(() => {
    console.log("C");
});

console.log("D");
- First synchronous code:console.log("A") → A,console.log("D") → D
- then goes to the Microtask Queue.Promise.then().

- setTimeout() callback goes to the Macrotask/Task Queue.
- The event loop gives priority to microtasks after the current synchronous execution finishes.


- What is a Promise?
- A Promise represents the eventual success or failure of an asynchronous operation. It has three states: pending, fulfilled, and rejected.

	-------------------------------
	async function getData() {

- Does await block JavaScript?:Not the entire JavaScript thread.
- await pauses the execution of that async function until the Promise settles; the runtime can continue handling other work.
- Promise.all() — very important
- const [user, orders, products] =
    await Promise.all([
        getUser(),
        getOrders(),
        getProducts()
    ]);
- They can progress concurrently rather than waiting for each call sequentially.
- If one Promise rejects, Promise.all() rejects.
- Promise.all() vs Promise.allSettled()
- Promise.all(): Promise.all([p1, p2, p3]): One failure → overall Promise rejects.
- Promise.allSettled():Promise.allSettled([p1, p2, p3]):Waits for all and tells you the status of each.
- Useful when you want:
   p1 → success
   p2 → failed
   p3 → success
- Promise.race() vs Promise.any()
- Promise.race():First Promise to settle wins:fulfilled OR rejected
- Promise.any():First Promise to fulfill wins.:It ignores rejected Promises until all have rejected.

ex: console.log(a);

var a = 10; output undefined

- But let?
ex: console.log(a);

- Because a exists in the scope but is in the Temporal Dead Zone (TDZ) until its declaration is initialized.
- Temporal Dead Zone:The Temporal Dead Zone is the period between entering a scope where a let or const variable is declared and the point where that variable is initialized. Accessing it during this period throws a ReferenceError."

What is React?:React is a JavaScript library for building user interfaces using reusable components. It uses a declarative programming model and efficiently updates the UI through reconciliation and the virtual DOM.
- What is a Component?:A component is a reusable piece of UI.
function User(){

return <h1>Hello Word</h1>
}
- What are Props?:function Parent() {
    return <User name="Ashish" />;
}
function User({ name }) {
    return <h1>Hello {name}</h1>;
}
Props are read-only from the child's perspective.

- What is State?:State is data managed by a component that can change over time and trigger a re-render.

- useState():const [count,setCount]=useState(0);
- What causes a React component to re-render?
- Its state changes
Its parent re-renders
A context value it consumes changes
Its subscribed external store data changes
- What is Virtual DOM?:"React maintains an in-memory representation of the UI and uses reconciliation to determine what changes need to be applied to the actual DOM."
- What is useEffect()?:useEffect is used to synchronize a component with external systems and perform side effects.
- What is useRef()?:useRef gives you a mutable value that persists across renders without causing a re-render when .current changes.
- useMemo: memoizes a computed value.It can avoid recalculating the value when dependencies haven't changed.
- useCallback():useCallback memoizes a function reference.
- What is React.memo()It memoizes a functional component so React can skip rendering it when its props haven't changed according to its comparison.
- What is Debouncing?:Wait until the user stops typing for a certain amount of time, then execute the function.
- What is Throttling?:Throttling limits how frequently a function can execute during a continuous stream of events.
- Large List — 100,000 records:A good solution is virtualization/windowing.
- Error Boundary:An Error Boundary catches certain errors during rendering/lifecycle of descendant components and lets you show fallback UI.
